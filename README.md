# PyNanoServer

Маленький HTTP-сервер на Python, написанный поверх «голых» сокетов, без Flask, Django и других веб-фреймворков. Проект учебный: хотелось своими руками разобрать, как устроен HTTP под капотом.

## Что умеет

- Принимает TCP-соединение и разбирает HTTP/1.1-запрос: стартовая строка, заголовки, тело (`application/x-www-form-urlencoded`).
- Маршрутизация по пути (`Router`) и обработчик по умолчанию для неизвестных путей (404).
- Формирует HTTP-ответ вручную: статус, заголовки, `Content-Length`, `Date`.
- Сессии по cookie: логин, выход, закрытые страницы (`/profile` без входа перенаправляет на `/auth`). Cookie выставляется с флагом `HttpOnly`.
- HTML-шаблоны из папки `templates/`.
- Настройки (`HOST`, `PORT`, `TEMPLATE_DIR` и др.) читаются из `config.py`.

## Запуск

```bash
python main.py
```

Откройте http://127.0.0.1:8989. Зависимостей нет, нужен только Python 3.

## Маршруты

| Путь | Что делает |
|---|---|
| `/` | главная; для вошедшего пользователя показывает панель |
| `/about` | страница «о проекте» |
| `/auth` | форма входа |
| `/auth/login` | `POST`: проверка логина, создание сессии, редирект |
| `/auth/logout` | `POST`: удаление сессии |
| `/profile` | профиль, только для вошедших |
| остальное | 404 |

## Устройство

```
main.py                 регистрирует маршруты и запускает сервер
handlers.py             обработчики страниц (наследуют Response)
server/
  server.py             сокет, цикл accept
  request_handler.py    разбор запроса: заголовки и тело
  router.py             путь -> обработчик
  response.py           сборка ответа, cookie, проверка сессии
  session_manager.py    хранилище сессий (uuid4 -> имя пользователя)
  config.py             загрузка настроек из .py-файла
templates/              HTML-страницы
```

## Ограничения

Это учебный сервер, не для продакшена:

- Обрабатывает одно соединение за раз (без потоков и `asyncio`).
- Запрос читается одним `recv(1024)`, поэтому большие запросы обрезаются.
- Сессии хранятся в памяти и пропадают при перезапуске.
- Демо-пользователь задаётся в config.py (по умолчанию demo / demo, можно переопределить переменными DEMO_USER и DEMO_PASSWORD), пароли не хешируются.
- Нет HTTPS, нет защиты от CSRF.
- Поддерживаются только статусы 200, 302, 404 и 500.

## Чему научился

Как устроен HTTP на уровне байтов, зачем нужны `Content-Length` и `\r\n\r\n`, как работают cookie и сессии, как разделить сервер на слои (сокет, разбор, маршрутизация, ответ).
